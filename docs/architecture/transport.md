# Transport engine

Packages and modules of the proton electromagnetic transport engine: the reference (Python)
backend of task V3-003A and the Warp CPU and CUDA backends, process pool and validation runner of
V3-003B. A requested backend that is unavailable (for example `warp-cuda` without a usable CUDA
device) raises `BackendUnavailableError`; nothing falls back to another backend. Design decisions:
[0037](../generated/decisions/0037-v3-architecture-and-conventions-baseline.md) (shared
functions, random streams, conventions) and
[0039](../generated/decisions/0039-proton-transport-engine.md) (models, step algorithm,
fail-closed contract). The models are described in [EM transport](../physics/em-transport.md).

## Module layout

| `ionmc.sources` | `PencilBeamSource` |

| `ionmc.simulation` | `Simulation`, `Result`, `GridResult`, `EnergyBalance`, `TransportCounters`, `capabilities()` |
| `ionmc.rng.philox` | Philox4x32-10 as a Warp function (`make_philox(real)`) and over Python integers, counter encoding |
| `ionmc.physics.kinematics`, `ionmc.physics.em` | shared Warp functions: kinematics, energy loss, straggling, scattering power, rotation |
| `ionmc.physics.scattering` | scattering length `X_S` (NumPy) |
| `ionmc.transport.funcs` | shared Warp functions: table bin location, DDA, step limits, hinge, scoring index, ray-box |
| `ionmc.transport.tables` | `TransportTables`: log-log stopping, range and inverse-range tables |
| `ionmc.transport.reference` | the Python history loop (reference backend) |
| `ionmc.transport.tally` | per-history tally rows, exact (Shewchuk/`fsum`) reduction, partial results, diagnostics assembly |
| `ionmc.transport.kernels` | the Warp transport kernel (`make_transport_kernel(real, diag)`) |
| `ionmc.transport.warp_driver` | tables/geometry on the device, chunked launches, per-chunk exact reduction |
| `ionmc.transport.pool` | spawn-context process pool (`python` and `warp-cpu`) |
| `ionmc.transport.run` | backend dispatch and reduction |
| `ionmc.transport.parity` | T1, T12 and T13 comparison statistics shared by tests and validation scripts |

Every Warp function is generated by a factory for one precision (`make_em(wp.float64)`,
`make_transport_funcs(wp.float32)`, ...). All of them are callable from Python scope with
`wp.float64` / `wp.float32` objects and from a compiled kernel; `tests/ionmc/test_shared_funcs.py`
compares both for every function (float64 within relative 1e-12 / absolute 1e-14, float32 within
1e-6 / 1e-6, integer outputs identical). The reference backend calls the float64 functions, so it
uses the same physics code that the Warp backends compile; its own loop only contains table reads,
bookkeeping, random draws, scoring and tallies.

## Usage

```python
config = SimulationConfig(
    source=PencilBeamSource(PROTON, position_mm=(0, 0, 0), direction=(0, 0, 1),
                            kinetic_energy_mev=100.0),
    geometry=BoxPhantom(lower_mm=(-30, -30, 0), size_mm=(60, 60, 150), material=WATER),
    scoring=(ScoringGrid(origin_mm=(-30, -30, 0), spacing_mm=(2, 2, 2), shape=(30, 30, 75)),),
    physics=PhysicsOptions(nuclear=False, stopping=BetheStoppingSource(), max_step_mm=2.0),
    run=RunOptions(backend="python", precision="float64", seed=1, n_histories=4, n_batches=2),
)
result = Simulation(config).run()
```

`Simulation(config)` validates at construction; nothing is simulated if validation raises.
Units follow decision 0037 (positions, spacings and step lengths in mm, energies in MeV,
densities in g/cm3, doses in Gy per primary). All grids use `origin_mm` = corner of voxel (0,0,0),
`spacing_mm`, `shape = (nx, ny, nz)` and C order `[ix, iy, iz]`.

* `PencilBeamSource(projectile, position_mm, direction, kinetic_energy_mev, energy_sigma_mev=0,
  lateral_sigma_mm=0)`: the direction is normalised (and recorded); the energy offset and the two
  lateral offsets (perpendicular to the beam, deterministic orthonormal basis, no axis privileged)
  are Gaussian. The beam travels in vacuum until it enters the geometry; a beam that misses the
  geometry is tallied as escaped.
* `VoxelGeometry(origin_mm, spacing_mm, shape, materials, material_index, density_g_cm3=None)`:
  world = union of voxels, vacuum outside. Vacuum voxels (density <= 0) are rejected.
* `ScoringGrid(origin_mm, spacing_mm, shape, name="dose")`: independent of the geometry grid.
* `PhysicsOptions(nuclear, stopping, straggling=True, multiple_scattering=True,
  e_cut_mev=2.0, max_step_mm=1.0, max_energy_loss_fraction=0.02, range_alpha=0.2,
  range_rho_f_mm=0.1, short_step_fraction=1e-3, ...)`: `nuclear` and `stopping` have no default
  (`nuclear=True` is rejected until nuclear interactions exist). Model names are
  `straggling_model="bohr_gauss_clamped_gamma_v1"`, `mcs_model="differential_moliere"`, `delta_electrons="local"`;
  any other string is rejected.
* `RunOptions(backend, precision, seed, n_histories, n_batches=20, cpu_workers=1,
  max_steps=None, allow_invalid_result=False, worker_timeout_s=None, memory_budget_bytes=2**31,
  chunk_histories=2**18)`. `chunk_histories` is a power of two of at least 2**10 and is recorded in
  the effective configuration.
* `DiagnosticsOptions(track_end_positions, escape_records, trace_histories)`: all off by default.

## Step algorithm (one history)

Stream key: the 64-bit seed (low and high 32-bit words). Counter: (history index, genealogy id 0,
block index, purpose). Source sampling uses purpose 1 block 0; transport uses purpose 0 with a block
counter starting at 0.

1. Source: normals from block (u0, u1) give the lateral offsets, from (u2, u3) the energy offset
   (the block is always drawn, the values are ignored for a zero sigma). A sampled energy outside
   `[E_cut, table maximum]` is not transported and increments `source_energy_out_of_range`. The
   particle is moved to the world box (`ray_box`); the voxel index is found by `floor` and clamped.
2. If `E <= E_cut`: the energy is deposited at the current position (tallied as `cutoff` and scored)
   and the history ends. This step draws nothing. If the step count reached `max_steps` the history
   ends as truncated (counter, energy tallied as `truncated`, never scored).
3. Read `S(E)` and `R(E)` of the current voxel's material, compute the distance to the next voxel
   plane (`dda_next`), the energy-loss limit `f E / S_lin`, the Geant4 range limit and the maximum
   step, and select the step `s` (`select_step`; ties go to the geometry).
4. Draw block A (four uniforms: hinge fraction `a`, polar-angle uniform, azimuth, reserved). It is
   drawn every step whatever the options.
5. Multiple scattering (if enabled): the variance is `s T_dM(E_mid)` with
   `E_mid = Rinv(R - rho s / 20)`, except on the first step of the particle's life (the `birth` state flag
   is true until a step of nonzero length completes), which uses `scattering_variance_birth` (analytic linearized
   average of the logarithmic term of `f_dM`, with `E1 = Rinv(R - rho s / 10)` limited to `E0`); it gives
   the polar angle; the direction is rotated at the hinge (leg 1 has length
   `a s` along the old direction). Leg 2 has length `(1 - a) s` along the new direction and is cut at
   the next voxel plane if that plane lies within it (relative tolerance 1e-9 in float64 so that
   planned boundary steps always cross); the particle then snaps onto the plane and the index is
   incremented on that axis. The travelled length is `s_act` = leg 1 + leg 2.
6. Energy loss for `s_act`: mean loss from the inverse-range expression
   (`E - Rinv(R - rho s_act / 10)`, or `S t` for `t < 1e-3 R`, or `E` when the whole residual range is
   travelled); with straggling, block B draws (one block per attempt, at most 64; exceeding the limit
   increments `straggling_rejection` and uses the mean); without straggling one block is drawn and ignored.
   The loss is limited to `E`. If the inverse-range energy ever exceeds `E` (round trip of the
   tables) it is clamped to `E` and `energy_inversion` is incremented (invalidates the result).

   This differs from the telescoping form of decision 0039 (`Rinv(R(E)) - Rinv(R(E) - t)`): the
   state energy `E` replaces `Rinv(R(E))`, because the round-trip offset of the tables would
   otherwise accumulate step after step along a track; the path independence of the CSDA relation
   is kept since the new energy is a function of the old one only.
7. Deposit `E_old - E_new` into every scoring grid by track-length apportioning: the deposit is
   distributed along both hinge legs proportionally to the path length inside each scoring voxel
   (`piece / s_act` of it per piece), using a per-grid incremental DDA over the leg (`seg_piece`, the
   transport DDA pattern; no floor-and-nudge); a piece outside a grid is tallied in that grid's `outside`.
   The energy left at the cutoff is a point deposit at the end point. Each piece is quantized (below).
   (V3-003A scored the midpoint; with steps comparable to the bin width that aliased with the bin edges.)
8. Leaving the geometry tallies the remaining energy as `escaped`. More than three consecutive
   zero-length steps tally the energy as `truncated` and increment `stall`.

## Deviations from the plan text of decision 0039 (accepted)

* `select_step(d_geo, s_eloss, s_range, s_max)` has no separate world distance: leaving the world is
  a geometry crossing whose next voxel index is outside the grid.
* `rotate_dir(u, theta, phi)` takes the angles (cosine and sine are computed inside).
* A stall is more than three consecutive zero-length steps.
* `backend="python"` with `cpu_workers > 1` is supported by the spawn pool (V3-003B); decision 0039 left
  it to V3-003B and the frozen T12 requires it.
* The inverse-range table has 800 points per decade (400 gave a round trip of 9.1e-6, too close to
  the 1e-5 limit of test U2).
* `RunOptions.memory_budget_bytes` bounds the accumulators; `PhysicsOptions.stopping` has no default.
* The energy loss uses the state energy (step 6 above); the cutoff energy is scored (see Results).

`TransportTables` is immutable: every array is read-only, the identity (source, effective I, dataset id
and hashes, material fingerprint, metadata) is stored as read-only mappings and tuples, and
`EffectiveConfig.summary()` returns deep copies.

## Grids of different size and alignment

Transport voxels (the `VoxelGeometry`, which sets the voxel planes that end steps) and scoring voxels
are independent: a scoring grid may have any origin (for example a half-voxel offset from the phantom
corner), spacing and shape, and the deposit of a step is shared among the voxels its legs cross. The geometry
may be a single box or a refined or shifted voxel grid, so the sensitivity of lateral and angular
observables to the transport grid can be probed with the reference backend: `escape_records` gives
position, direction and energy of every escaping particle (exit angles, `theta_rms`), the scoring grids
give deposits for lateral second moments. One restriction applies to such studies: `max_step_mm` must not
exceed the smallest scoring spacing (any axis), so a fine lateral scoring grid forces short steps.

## Fail-closed rules

Each rule raises before any transport and nothing is clamped or substituted (test C1,
`tests/ionmc/test_config_validation.py`):

* the projectile is not exactly the canonical proton (all fields; projectile fields are validated
  when a `Projectile` is built); a stopping source that returns a table for another projectile or
  material than requested (the complete `Material` definition must be identical: composition,
  density, I and density-effect parameters); `nuclear=True`; unknown model names;
* `backend="python"` with `float32`; `warp-cuda` without a usable CUDA device (`BackendUnavailableError`, no
  fallback); `cpu_workers > 1` on `warp-cuda`, more workers than histories or more than 256;
  accumulators (one private copy per worker process) above `memory_budget_bytes`;
* `trace_histories > 0` with float32 (the trace is the float64 trajectory-parity reference), above
  `n_histories`, or with trace buffers above 1 GiB; `chunk_histories` that is not a power of two or below 2**10;
* `n_histories` outside `[1, 2**32]`, not a multiple of `n_batches`, `n_batches < 2`, `seed` outside `[0, 2**64)`;
* source energy outside `[2 E_cut, table maximum]`, `energy_sigma_mev` above 5 % of the energy,
  a zero direction; a stopping-table minimum above `E_cut / 2`; a material the stopping source cannot
  provide a table for;
* material index out of range, density <= 0, spacing <= 0, wrong shapes, non-finite values;
* zero or more than four scoring grids, duplicate grid names, accumulators
  (`n_batches * voxels * bytes`) above `memory_budget_bytes`;
* `max_step_mm` larger than the smallest scoring spacing (a leg then crosses at most one plane
  per axis of a scoring grid, which bounds the DDA walk of the track-length scoring);
* `n_histories / n_batches` times the largest source energy above the capacity `2**62` quanta of a fixed-point
  voxel accumulator (quantum 2**-30 MeV);
* `max_steps * 65 >= 2**32` (the block counter bound).

`max_steps` defaults to a conservative bound computed from the CSDA path length, the step limits
and the voxel size; the value and its origin (`"user"` or `"computed"`) are recorded in the
`EffectiveConfig`, together with the normalised direction, the table identity (SHA-256 and I-values),
`X_S` of each material, the precision, the production flag (true only for float32 Warp backends)
and the uniform mapping.

After the run a nonzero transport-limit counter makes the result invalid: `run()` raises
`TransportLimitError` (its `.result` is the invalid result) unless
`RunOptions.allow_invalid_result` is set, in which case `result.valid` is `False` and every grid
result is flagged `valid = False`. Counters: `step_truncation`, `stall`, `straggling_rejection`,
`genealogy_overflow` and `queue_overflow` (both always 0 until secondaries exist),
`source_energy_out_of_range` and `energy_inversion`.

## Results

`Result` fields: `valid`, `requested_config`, `effective_config`, `backend`, `device`, `precision`,
`seed`, `rng`, `n_histories`, `n_batches`, `grids`, `energy_balance`, `counters`, `timings`
(seconds: setup, compile, transport, reduce, total), `environment`, `diagnostics`.

Per scoring grid (`GridResult`, everything per primary history):

| Field | Meaning, unit |
|---|---|
| `energy_mev`, `energy_std_mev` | mean deposited energy per voxel and its standard error [MeV] |
| `dose_gy`, `dose_std_gy` | dose and its standard error [Gy] (1 MeV/g = 1.602176634e-10 Gy), NaN where the voxel has no mass |
| `relative_uncertainty` | `std / mean`; NaN where the mean is 0 (an undefined uncertainty is never reported as 0) |
| `defined_mask` | voxels with positive mean energy and positive mass |
| `mass_g` | exact overlap integral of the geometry density over the voxel [g] (0 outside the geometry) |
| `n_nonzero_batches`, `sparse_mask`, `low_batch_count` | batches with a nonzero sum; defined voxels with fewer than `B/2` of them; `B < 10` |
| `batch_energy_mev` | per-batch estimates `E_b / (N/B)`, shape `(B, nx, ny, nz)` |

Statistics use the batch method: history `h` belongs to batch `h mod B`, the mean is the mean of the
per-batch estimates and its variance `sum (x_b - mean)^2 / (B (B - 1))`.

`EnergyBalance` (MeV summed over all histories, every tally accumulated independently):
`initial`, `step_deposit`, `cutoff`, `escaped`, `truncated`, `unaccounted`, and per grid `in_grid` and
`outside`. `cutoff` is energy that is deposited locally below `E_cut` and scored like any other
deposit, so it is part of `in_grid + outside`. The identities are
`initial = step_deposit + cutoff + escaped + truncated + unaccounted` and, per grid,
`in_grid + outside = step_deposit + cutoff` (`closure_residual_mev`, `relative_residual`,
`grid_relative_residual`). The tests require a relative residual of at most 1e-12 for the float64
reference backend (test T4, T11).

## Diagnostics

`track_end_positions`: `end_position_mm`, `end_code` (0 cutoff, 1 escaped, 2 truncated, 3 source
rejected, 4 missed the geometry) and `end_energy_mev` per history; `escape_records`: history,
position, direction and energy of every escaping particle; `trace_histories = K`: a per-step trace of
the first K histories (`ionmc.transport.reference.TRACE_COLUMNS`: voxel index, step reason, blocks drawn,
straggling attempts, position, direction, energy, deposit, step length). The trace is the reference
for trajectory-level parity with the Warp backends.

## Warp backends

`warp-cpu` and `warp-cuda` run one kernel thread per history (`ionmc.transport.kernels`). The step loop is a
statement-by-statement copy of `reference._history`: the same branches in the same order and the same expression
order, all physics through the shared `@wp.func` functions, so the float64 kernel and the Python reference follow
the same trajectory (test T1). `make_transport_kernel(real, diag)` is cached per precision and diagnostics flag
(`module="unique"`, backward off); the variants are float32, float32 with diagnostics, float64 and float64 with
diagnostics, and the trace is validated for float64 only (float32 with a trace is rejected). Inputs are
structure-of-arrays Warp arrays plus a per-precision `wp.struct` of scalars. Outputs: the deposit grid
`edep[B, sum(n_voxels)]` of int64 fixed-point quanta (integer atomic adds into batch `h mod B`), per-history
float64 `tally_rows[chunk, 6 + 2 G]` (tallies, outside deposits, quantization residuals) and int32
`counter_rows[chunk, 8]` (each written by its own thread), and with diagnostics the end state (position,
direction, energy, code) per history.

**Exact tallies.** The host reduces the per-history rows with exact summation (`exact_components`: repeated
`math.fsum` of the residual gives an expansion whose exact sum is the exact column sum, and expansions of chunks
and workers are concatenated before the final `fsum`). Tallies are therefore bit-identical for any partition
of the histories (chunks, workers); counters are int64 sums. The reference backend uses the same row reduction.

**Fixed-point deposit grids.** Every apportioned deposit piece is rounded to the nearest multiple of
q = 2**-30 MeV (`floor(x / q + 1/2)`, a deterministic function of the piece) and added to an int64 voxel
accumulator. Integer addition is associative, so the grids are bit-identical for any chunk size and any
number of workers within a precision (test T13 requires `edep_identical`; the old relative bounds are reported
as secondary numbers). The rounding error is at most q/2 per piece (a random walk of at most q/2 sqrt(N)
over N pieces in one voxel) and its sum is tallied per history and grid, so the balance
`in_grid + quantization + outside = step_deposit + cutoff` closes in float64. The conversion to float64
and the sum over workers happen at the reduction. Capacity: a voxel holds at most `2**62` quanta (about
`4.3e9` MeV); validation rejects runs whose per-batch energy could reach it, and a voxel at or above it after
a run raises the counter `accumulator_overflow`, which invalidates the result. Pieces are computed in the
backend precision, so a float32 run apportions to float32 rounding (about 1e-7 of a step deposit) before
quantizing.

**Chunking.** A range of histories is launched in chunks of at most `chunk_histories`; after each chunk the rows
are reduced and the deposit grid stays on the device. On CUDA, `.numpy()` of the rows synchronises, and the
seconds of every chunk are recorded in `Result.transport_report` (long kernels may be killed by a display
watchdog on some hosts), together with the compile/load seconds and the register count of the kernel.

**Trace protocol.** `trace_histories = K` allocates `int32 [K, max_steps, 8]` (history, step, ix, iy, iz, reason,
blocks, attempts) and `float64 [K, max_steps, 9]` (position, direction, energy, deposit, step length) buffers and
the number of rows per history; a history stops at `max_steps`, so the buffer cannot overflow. The diagnostics
dictionary has the same layout as that of the reference backend, so `ionmc.transport.parity.compare_traces`
compares them: discrete columns exactly, continuous columns within rtol = atol = 1e-10.

## Process pool

`cpu_workers = W > 1` (backends `python` and `warp-cpu`) uses spawn-context `Process` objects with one-way
pipes (not `ProcessPoolExecutor`). Worker `w` transports the histories `[floor(wN/W), floor((w+1)N/W))` with
private accumulators; its payload is the pickled `EffectiveConfig` (immutable mappings are pickled as
dictionaries). The parent compiles the Warp kernel before spawning, workers inherit `WARP_CACHE_PATH`, and every
worker reports its own kernel load time (`compile_s` in `transport_report`), so a cache miss is visible. Whether
workers reuse the compiled `module="unique"` kernel is checked by the test `test_t13_warp_cpu_one_versus_three_workers`.
If a worker raises, dies, or the run exceeds `worker_timeout_s`, all workers are terminated (killed after a grace
period) and `TransportWorkerError` is raised; no partial result is returned. Scripts that start a pool need the
`if __name__ == "__main__":` guard (spawned workers re-import `__main__`).

## Validation runner

`validation/scripts/transport/run_suite.py --suite {lv,hr} --out validation/generated/transport/<new-dir>
--expected-sha <sha>` runs the local-validation (CPU) or host-runner (CUDA) suite of
`validation/plans/v3-003-acceptance.md`. It is a Python script because the host runner executes argv without a shell.
It refuses an existing output directory (and one outside `validation/generated/` or `benchmarks/generated/`),
requires the SHA to equal `git rev-parse HEAD` when git can read the tree (a snapshot without `.git` records the
declared SHA), writes `environment.txt` (versions, hardware, SHA, dirty state, script hashes), archives every step
in `NN-name.txt` with a header and an `# exit=` trailer, writes the fixed `manifest.txt`, and
`summarize.py` verifies everything and writes `summary.json`. Any failed step, missing file or mismatch makes the
exit status non-zero. `--scale` below 1 reduces all history counts; such a run is labelled non-conformant in the
summary. Steps (`steps.py`): T1, T2, T8, T9, T10, T12, T13 (workers, chunks) and T14 on top of the pytest suites
(T2-T4, T11, C1 on warp-cpu; CUDA tests with `IONMC_REQUIRE_CUDA=1`). The HR suite needs only numpy, Warp and pytest.

Implementation choices forced by engine rules (listed so the criteria are not read as met more strongly than
measured): `max_step_mm` must not exceed the smallest scoring spacing, so T8/T14 take the lateral sigma from the
exit positions of particles leaving a water slab of the stated thickness (the Fermi-Eyges A2 quantity) instead of
0.2 mm deposit bins; T9 uses 1 mm IDD bins (the deterministic T9-CI check in `test_transport_scoring.py` guards the scoring); T10 uses the distribution of the projected track-end depth
(oblique deposit grids alias when projected); the T14 along-beam shift changes the slab thickness by half a voxel,
so T14 compares the ratios to the quadrature at the actual thickness; the T14 negative control (a diagnostic
switch for the hinge angle) is not implemented. T12 compares independent samples with distinct seeds using the
batch-method standard errors (Student-t for few batches; the batch counts are recorded). The deposit grids of T13 must be bit-identical.

Note on T9: with the midpoint scoring of V3-003A and `s_max` comparable to the IDD bin width, point deposits
aliased with the bin edges (deviations of tens of percent relative to a 0.1 mm-step run in the deterministic
case); track-length apportioning removes this, and the T9-CI test records the bounds.

## Benchmarks

`benchmarks/transport/bench_em.py` measures EM-only transport (no nuclear interactions) and writes aggregate JSON
under `benchmarks/generated/`: wall time, histories per second, cold start (empty kernel cache), compile, host and
kernel seconds, peak RSS, three repeats, each in a fresh process. There are no performance targets yet
(`targets: null`; frozen in V3-012), so the numbers are informative only and labelled "EM-only".

## Reference backend performance

The reference backend is slow by design: every call of a Warp function from Python scope goes
through Warp's overload resolution and every arithmetic operation on Warp scalars is a library
call. It is meant for small numbers of histories, inspection and cross-checks.
