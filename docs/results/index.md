# Persisted results

`ionmc run` (and the Python function `ionmc.results.save`) write a run as a **result
bundle**: a directory that carries its own description, so that a bundle can be read, checked and
reported without the program that wrote it. The exact format is in the
[results format reference](format.md); the commands are in the [CLI](../cli.md); the steps from a
configuration file to a checked bundle are in the [workflow](../workflow.md).

## Files of a bundle

| File | Content | Role |
|---|---|---|
| `result.json` | strict canonical JSON: schema id and version, the requested and the effective configuration, provenance, run, statistics, accounting, units, the array catalogue and the `files` map | authoritative |
| `arrays.npz` | every array, in a deterministic zip of `.npy` members (read without pickle) | authoritative |
| `report.md` | the human-readable report | derived |
| `plots/*.svg` | depth profiles and, for LET tallies, LET depth profiles | derived |

The report and the plots are pure functions of `result.json` and `arrays.npz`: they can be
regenerated byte for byte (`ionmc report DIR`), and `ionmc report DIR --check` compares the
regeneration with the bytes on disk. A run that completed with an invalid result (only possible with
`allow_invalid_result = true`) is written with `valid = false` and a banner at the top of the report.

## What is stored, and what is not

- `requested` is the configuration as the user gave it; `effective` is what the engine resolved
  from it (defaults, derived values, the stopping model in effect). Every difference between the two
  follows a fixed rule (see the [reconciliation table](../configuration/index.md#requested-and-effective)); anything else
  is refused before transport.
- Input files referenced by a configuration (voxel arrays, lookup tables) appear in
  `input_manifest` with their sha256; their content is not copied into the bundle, except for the
  geometry arrays of the grid, which are persisted.
- No stopping, range, LET-water or nuclear table values are ever persisted, and no value derived
  node by node from licensed data. Only identities and digests are recorded; an array-name allowlist
  in the writer enforces this.
- Undefined values are `NaN` in arrays (with a mask) and `{"value": null, "status": "undefined",
  "reason": ...}` in JSON; they are never written as zero.
- The only places where an absolute path of the writing machine can appear are the path set
  `/run/output_path`, `/run/cache_dir`, `/input_manifest/base_dir`,
  `/input_manifest/config_file/path`, `/input_manifest/files/<i>/path` and the `cache_dir` keys
  inside `/effective/stopping` and `/effective/nuclear`. The report and the plots never print them.

## Two verification tiers

**Tier 1, `ionmc verify DIR`.** Reads only `result.json` and `arrays.npz`; never the data cache,
an input file or transport. It checks the schema and version, every file and array hash, the
allowlist, the shapes against the grids, the accounting identities and the bindings of the
requested configuration to the run, the arrays, the stopping identity and the effective values
that do not depend on tables. It fails closed (`ResultFormatError`, exit 6) under explicit
resource budgets, so an untrusted bundle cannot exhaust memory. What tier 1 does not bind is
listed in the `binding_limits` output of `ionmc verify`: those parts are protected by the file
hashes only (see [what tier 1 binds](format.md#what-tier-1-binds)).

**Tier 2, `ionmc verify DIR --rederive --cache-dir DIR2`.** Explicitly trusts the local
installation and its data cache (and, with `--inputs ROLE=PATH`, the named input files, each
checked against the manifest sha256). It rebuilds the configuration from `requested`, runs the same
validation and compares the effective summary byte for byte with the stored `effective`. A bundle
written by an earlier code version that differs is reported as differing, with the pointers; it is
not thereby invalid (tier 1 decides validity). A missing cache object is a tier-2 failure, never a
tier-1 one.

## Reading a bundle from Python

```python
from ionmc.results import load

loaded = load("out/proton_box")     # tier 1; raises ResultFormatError on any defect
print(loaded.binding_limits)
```

Every budget of `load` is a keyword argument (see the [budgets](format.md#reader-budgets)).
