# V3-005D elastic attribution — exploratory records (Amendment 19; never evidence)

These directories are committed copies of the outputs that the modules under `validation/scripts/elastic_attribution/` write to `validation/generated/elastic_attribution/` (git-ignored). Each report starts with the banner "Exploratory, report-only (Amendment 19); not evidence; changes no row." and lists its inputs with sha256 and the command that regenerates it.

## Git policy for these exploratory records (reconciliation of decision 0041, dated 2026-10-14, after Codex REVIEW-a7c99b45)

Decision 0041 rules that Git holds no raw or derived nuclear data, only registry entries, manifests, synthetic fixtures and aggregate statistics. For the V3-005D records this is applied as an **explicit allowlist** per module (`GIT_ALLOW` in each `validation/scripts/elastic_attribution/*.py`, enforced by `common.git_projection` and the tests in `tests/ionmc/test_elastic_attribution_de0.py`):

- **Committed:** dimensionless ratios (model/data, ionmc/Geant4, table/formula), per-primary probabilities and rates, kinematic and geometric statistics (angles, medians, exceedance probabilities, tail moments, mean secondary energies), kernel integrals per primary (K_w, K*, G), counts, flags, verdicts, seeds, hashes and provenance.
- **Never committed:** absolute cross-section values of any origin (table, formula or experiment; mb or mb/sr), sampled or tabulated angular/energy distributions (histograms, CDFs, per-point arrays, neighbour ratios), PDG or EXFOR points and their coordinates. These live only in `validation/generated/` (git-ignored) and in the reference cache.
- Every committed Markdown body is rendered from the committed JSON, so a report cannot carry anything the projection removed.

## Records

- `de0/` — D-E0 kernels (K_w, K* as frozen and in the corrected-sign form, G, θ_w, T), reconciliation of the planning expectation, H6 case-file check. `quarantine-data-seen.json` holds shape parameters fitted to V11; it is never cited (Amendment 19 addendum (a)3).
- `de1/` — D-E1 per-dataset shape comparison. Every committed JSON here is the **Git projection** written by `common.write_outputs` into `validation/generated/elastic_attribution/<step>/git/` (decision 0041: Git holds no raw or derived nuclear data, only aggregate statistics): the experimental values (`data_mb_sr`, `rel_err`), the PDG points and every per-point array (angles, model values, model/data ratios, Rutherford and family curves — from which the data would be losslessly recoverable) are removed by `common.git_projection`; the Markdown reports are written by the same writer as header (command, input hashes) + marker + `render_report(projection)`, a pure function of the projected JSON, so a report cannot carry anything the projection removed; `tests/ionmc/test_elastic_attribution_de0.py` asserts that every committed JSON passes `common.git_safety_violations` and equals its own projection, and that every committed report body equals the module's rendering of the committed JSON. Per-angle model/data ratios, neighbour-point ratios and PDG points (values and energies) are not in Git; the V10-A row of the archive of record holds its own per-angle verdicts. Kept: window integrals and ratios, minima diagnostics (angles, drop significance, implied radius), the data-seen one-parameter R fits (diagnostic only) and the angle range per dataset. The complete records are regenerated into `validation/generated/` (git-ignored) by the committed modules.
